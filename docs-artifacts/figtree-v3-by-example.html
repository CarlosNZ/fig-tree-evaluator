FigTree v3 by Example

Nine expressions, each one step harder than the last — from reading a name out of a form to evaluating a whole dashboard config with per-hole degradation and a shielded timeout.

Every expression here follows the Agreed areas of the v3 spec: operator and parameter names, the shorthand grammar, reference namespaces, the reserved-key set and the null policy. Following the working docs' own convention: behaviours are binding, encodings are illustrative — result values and which errors occur are the spec; issue codes, error message wording and HTTP response bodies are dressed for the page.

Three rules, then the ladder

An expression is any JSON

fig.evaluate(config, { data }) walks the whole value. Recognised nodes evaluate in place; everything else passes through untouched. Deep evaluation is the only semantics — there is no shallow mode and no second method.

$ has exactly two jobs

In key position it invokes an operator or fragment: { $if: … }. In string-value position it reads a named scope: '$data.user.name'. Any other $ is inert data that validate() warns about.

Every node has two faces

Canonical { operator: 'if', condition, then, else } and shorthand { $if: [c, t, e] }. An array payload is positional, a plain object is named, anything else is one argument. Shorthand normalises away at parse.

01

Read a value, render a sentence

The smallest useful expression: pull a couple of fields out of the evaluation data and render them into text.

$data references buildString shorthand vs canonical null renders empty
Data
{
  user: { firstName: 'Steve', lastName: 'Rogers', title: 'The First Avenger' },
  organisation: { name: 'The Avengers' },
}
Expression the one-liner — reference tokens, no substitutions object at all
{ $buildString: 'Hello {{$d.user.firstName}} — {{$d.user.title}}, {{$d.organisation.name}}' }
Result
'Hello Steve — The First Avenger, The Avengers'
Same operator, other two faces
// positional: an array payload maps onto ['template', '...substitutions']
{ $buildString: ['%1 %2', '$data.user.firstName', '$data.user.lastName'] }
// → 'Steve Rogers'

// canonical + named substitutions: an object payload means named tokens
{
  operator: 'buildString',
  template: 'Dear {{first}} {{last}}',
  substitutions: { first: '$data.user.firstName', last: '$data.user.lastName' },
}
// → 'Dear Steve Rogers'
  • One operator, three faces. The $name key is shorthand; its payload type picks the calling convention — array is positional, plain object is named, anything else is a single argument. Parse normalises all of it into the canonical form, so tooling and the evaluator only ever see { operator: 'buildString', … }.
  • Two token styles, one per payload shape. %1-style tokens pair with an array; {{name}}-style tokens pair with an object. A token whose body is itself a reference — {{$d.user.title}} — is that reference, so the one-liner needs no substitutions at all. $d is the alias for $data; both normalise to $data.
  • A missing path is null, and buildString renders null as the empty string. {{$d.user.middleName}} produces nothing — never the text "null". Absence is not failure.
  • An unbound token renders itself. '%3' with two substitutions comes out as the literal text %3: the end user sees slightly odd output and keeps working, the admin they report it to sees exactly what is wrong — and validate() flagged it at authoring time, with a renumber hint.
  • Reference tokens are recognised in literal templates only. A template arriving from $data or an API is runtime data and is never scanned for references — it can never mint itself a data read.
02

Decide something

A cinema's entry rule: the filmgoer must meet the film's age rating — unless a parent is with them, in which case 13 is enough.

if greaterThanOrEqual symbol aliases lazy branches
Data
{
  film:   { title: 'Deadpool & Wolverine', minAgeRating: 17 },
  patron: { age: 12, isParentAttending: true },
}
Expression
{
  $if: {
    condition: '$data.patron.isParentAttending',
    then: { $greaterThanOrEqual: ['$data.patron.age', 13] },
    else: { $greaterThanOrEqual: ['$data.patron.age', '$data.film.minAgeRating'] },
  },
}
Result a parent is attending, but 12 is still under 13
false
The same rule, terse every alias is symbolic; there are thirteen in total
{
  '$?': [
    '$d.patron.isParentAttending',
    { '$>=': ['$d.patron.age', 13] },
    { '$>=': ['$d.patron.age', '$d.film.minAgeRating'] },
  ],
}
  • Exactly one branch evaluates. then and else are lazy parameters — declared in metadata, not hand-rolled — so a branch holding an HTTP call never fires when the condition goes the other way. The same laziness governs match branches, vars and fragment arguments.
  • else is optional, and omitting it means null. That is success-with-null, not failure: a fallback will not stand in for a missing else, because fallback catches failures only. "Value when the condition isn't met" is precisely what else is for.
  • Comparisons take exactly two operands, both numbers or both strings — no implicit coercion anywhere in v3. greaterThan is strictly greater; greaterThanOrEqual is its own operator rather than a strict: false flag.
  • A null operand propagates: the comparison resolves to null, which reads falsy in the condition above. Where absence must be distinguished from a real comparison, test for it — { $notEqual: ['$data.patron.age', null] }.
  • Word aliases are gone. Canonical names are camelCase and exact-match: $If, PLUS and not_equal are unknown-operator errors, caught at parse.
03

When the data isn't there

A profile card assembled from patchy data. Note the root: it is an ordinary object with expressions embedded in it, not a single node.

plain-literal root firstOf get + missingPathDefault fallback
Data no nickname key at all; phone is a stored null
{
  user: { name: 'Mohini', phone: null, prefs: { locale: 'en-NZ' } },
}
Expression
{
  card: 'profile',
  displayName: { $firstOf: ['$data.user.nickname', '$data.user.name', 'Anonymous'] },
  contact: { $buildString: 'Phone: {{$d.user.phone}}' },
  timezone: { $get: { path: 'user.prefs.timezone', missingPathDefault: 'Pacific/Auckland' } },
  locale: '$data.user.prefs.locale',
  avatar: {
    $http: 'https://api.example.com/avatar/mohini',
    fallback: 'https://cdn.example.com/avatar/default.png',
  },
}
Result the avatar API is returning 503
{
  card: 'profile',
  displayName: 'Mohini',
  contact: 'Phone: ',
  timezone: 'Pacific/Auckland',
  locale: 'en-NZ',
  avatar: 'https://cdn.example.com/avatar/default.png',
}
Three tools, three different triggers
'$data.user.x'                              // → null. The everyday read.
{ $firstOf: [a, b, 'default'] }             // fires on null OR missing
{ $get: { path: 'a.b', missingPathDefault: 'x' } }  // fires on a MISSING path only
{ …, fallback: 'x' }                        // fires when the node actually FAILED
  • Absence is not failure. A missing $data path resolves to null and composes onward; only an operation that genuinely broke — a 503, a type miss, a division by zero — is a failure, and only failures reach fallback. Everything above hangs off that one distinction.
  • user.phone is a genuine stored null, which is why missingPathDefault would not fire on it — that parameter triggers on a missing path only, preserving the null/missing distinction that a bare reference deliberately erases. firstOf treats both the same.
  • firstOf evaluates candidates in order and stops. The sequencing is semantics, not optimisation: a backup HTTP call placed second must not fire when the first candidate answered. It skips only null — "", 0 and false are answers.
  • card is a constant and locale is a bare reference. Constant subtrees are classified at parse and returned by identity — there is no traversal cost per evaluation. A reference is a value, not a node, so it carries no modifiers: for a default, use get or firstOf.
  • Shorthand nodes may carry reserved sibling keys — { $http: '…', fallback: … } is legal, and so are useCache, vars and //. Any other sibling key is a hard parse error.
04

More than two ways to go

A card-game recommender: branch on player count, then on preferred difficulty. match is how a decision tree stays readable past the second if.

match branch keys are strings lazy branches dynamic lookup tables
Data
{ numberOfPlayers: 3, ageOfYoungestPlayer: 12, preferredDifficulty: 'easy' }
Expression
{
  $match: {
    value: '$data.numberOfPlayers',
    branches: {
      1: 'Solitaire',
      2: { $if: [{ $lessThan: ['$data.ageOfYoungestPlayer', 10] }, 'Go Fish', 'Cribbage'] },
    },
    default: {
      $match: {
        value: '$data.preferredDifficulty',
        branches: { easy: 'Uno', challenging: '500' },
        default: 'Cheat',
      },
    },
  },
}
Result 3 players matches no branch → default → 'easy'
'Uno'
The other mode a computed branch map — the everyday lookup table
{
  $match: {
    value: '$data.status',
    branches: '$data.statusLabels',   // evaluated whole, eagerly; the matched value returns verbatim
    default: 'Unknown',
  },
}
  • Matching is by canonical string form. Branch keys are JSON object keys, so they are always strings: the number 1 matches the key "1", true matches "true". A null match value matches no branch and falls through to default.
  • Only the matched branch evaluates. The other branches are structure, not work — the compiled node holds each branch as a deferred handle, and constant branches are pre-resolved.
  • No match and no default is a runtime failure, catchable by fallback like any other. v2's magic fallback key inside the branch map is gone; the default branch is a declared parameter now.
  • Branches live in their own parameter. v2 let branch values hang off the node as flat keys, which meant a branch called "operator" resolved to the node's own property. In v3 the map is parameter data — though a literal map whose keys collide with the node grammar (operator, fragment) fails loudly at parse. Supply such a map dynamically instead; a built object's keys are runtime data and are never classified.
  • Mode is decided statically at parse — a plain object is the branch map, a node or reference supplies the map at runtime — so validate() and the editor always know which they are looking at, and can badge the dynamic ones.
05

Work on a list

A picking slip from an order. Iteration is first-class in v3 — the gap that v2 filled host-side with custom functions.

[*] projection map / filter / some $element · $index join · length · arithmetic
Data
{
  order: {
    id: 'A-1042',
    lines: [
      { sku: 'FIG-01', name: 'Fig sapling',    qty: 2, unitPrice: 24.95 },
      { sku: 'POT-11', name: 'Terracotta pot', qty: 2, unitPrice: 18.5 },
      { sku: 'GLV-02', name: 'Pruning gloves', qty: 0, unitPrice: 12 },
    ],
  },
}
Expression
{
  reference: '$data.order.id',
  allSkus: '$data.order.lines[*].sku',
  itemCount: { $length: { $filter: ['$data.order.lines', { $greaterThan: ['$element.qty', 0] }] } },
  summary: {
    $join: {
      values: {
        $map: {
          input: { $filter: ['$data.order.lines', { $greaterThan: ['$element.qty', 0] }] },
          each: { $buildString: '{{$e.qty}} × {{$e.name}}' },
        },
      },
      delimiter: '; ',
    },
  },
  total: {
    $round: [
      { $plus: { $map: ['$data.order.lines', { $multiply: ['$element.qty', '$element.unitPrice'] }] } },
      2,
    ],
  },
  anyBackordered: { $some: ['$data.order.lines', { $equal: ['$element.qty', 0] }] },
}
Result
{
  reference: 'A-1042',
  allSkus: ['FIG-01', 'POT-11', 'GLV-02'],
  itemCount: 2,
  summary: '2 × Fig sapling; 2 × Terracotta pot',
  total: 86.9,
  anyBackordered: true,
}
  • [*] is a projection segment in the shared path grammar — it belongs to references, get.path and returnPath alike. lines[*].sku applies the rest of the path to every element and collects the results in order. Without it, lines.sku is an honest miss: name is not a key of an array. v2 projected implicitly; v3 makes you write it.
  • Inside each, $element and $index name the current element and position (aliases $e and $i; $index is zero-based, bare only). Nest iterators and name the outer one — as: 'order' binds $order and $orderIndex and turns off $element for that iterator, so there is one way to refer to each thing.
  • Elements evaluate in parallel, always. map and filter need every element; find, some and every resolve at the first decider and cancel the rest. A failure the decision does not depend on is discarded with the cancelled work.
  • Empty input never errors: map/filter → [], some → false, every → true, find → null. A null input is a different matter — that's a runtime type error, and the softener is nullInputDefault: [], opt-in per node or host-wide via operatorDefaults.
  • A node can supply a whole array parameter. { $plus: { $map: […] } } is a single non-array payload, which binds the rest parameter dynamically — that's how the line totals get summed without an intermediate.
  • The filter is written twice. Rung 06 fixes that.
06

Name the repeated thing

The same picking slip with a vars block — and a comment, which is legal anywhere in an authored expression.

vars on a plain literal $vars · $v lazy + memoised // comments
Expression same data as rung 05
{
  '//': 'Picking-slip block. Backordered lines are excluded — see CONF-412.',
  vars: {
    picked: { $filter: ['$data.order.lines', { $greaterThan: ['$element.qty', 0] }] },
  },
  reference: '$data.order.id',
  itemCount: { $length: '$vars.picked' },
  firstSku: '$vars.picked[0].sku',
  summary: {
    $join: {
      values: { $map: ['$v.picked', { $buildString: '{{$e.qty}} × {{$e.name}}' }] },
      delimiter: '; ',
    },
  },
}
Result both vars and // are consumed — neither appears in the output
{
  reference: 'A-1042',
  itemCount: 2,
  firstSku: 'FIG-01',
  summary: '2 × Fig sapling; 2 × Terracotta pot',
}
  • vars is functional on a plain object literal, not only on nodes. That is what makes the whole-config case work: with no identity operator to hang a block on, and no wish to nest every config under a $let-style wrapper, the block goes directly on the object it scopes. The key is consumed and never appears in the output.
  • Lazy and memoised. picked evaluates at most once per scope instance per evaluation, on first reference — three references, one filter. A var referenced only inside a branch that never runs never evaluates at all, so a var holding an HTTP call costs nothing on the paths that don't need it. Parallel branches share the one in-flight evaluation.
  • Lexical, and drillable. A var is visible to its object and every descendant, and you can path into its result — '$vars.picked[0].sku', or '$vars.country[0].name.common' for an API record. v2's alias nodes could do neither.
  • Fragment bodies are sealed. A fragment called from inside this scope sees its own vars and its $params — never the caller's. Pass what it needs as arguments.
  • // is a comment key, legal on nodes, inside vars and parameters maps, and on plain data objects. Its value is any JSON, never parsed or evaluated, and stripped everywhere at parse. One per object, since JSON keys are unique.
  • Var names are plain identifiers with no $ prefix, so they cannot collide with operators, fragments or data keys. Cycles are a validation error; shadowing an outer name is legal but draws a warning, as does declaring a var nothing references.
07

Reach outside the config

The classic dependent dropdown: pick a country, get its cities. The list comes from an online database, and the field still has to render when that call fails.

http returnPath visible wiring result caching
Instance
import { FigTree, coreOperators, httpOperators } from 'fig-tree-evaluator'

const fig = new FigTree({
  operators: [coreOperators, httpOperators()],   // no argument → FetchClient over global fetch
  data: { api: 'https://countriesnow.space/api/v0.1' },
  cache: { maxSize: 200 },
})
Expression
{
  vars: {
    cities: {
      $http: {
        url: { $buildString: '{{$d.api}}/countries/cities' },
        method: 'post',
        body: { country: '$data.form.country' },
        returnPath: 'data',
        timeout: 4000,
      },
      fallback: ['Loading…'],
    },
  },
  label: { $buildString: 'Cities in {{$d.form.country}}' },
  options: '$vars.cities',
  count: { $length: '$vars.cities' },
}
Result evaluated with { data: { form: { country: 'India' } } }
{
  label: 'Cities in India',
  options: ['Abohar', 'Abrama', 'Achalpur', 'Achhnera', '…'],
  count: 4176,
}
  • I/O operators exist only when they are registered. On an instance without httpOperators(), { $http: … } is an unknown-operator error at parse — the author's toolchain catches it, not the end user's runtime. There is no ambient network capability: v2's silent browser fetch fallback is gone, and the convenience survives one level down, in FetchClient() itself.
  • returnPath uses the shared path grammar, [*] included. returnPath: 'data[*].name' would project one field out of a list of objects with no map — which is what v2's single-key-object collapse was reaching for, without dispatching on how many columns happened to come back.
  • Caching keys on the resolved request. useCache defaults to true for I/O operators; the key is built from the effective request, not the authored spelling, so switching country forks the entry naturally and re-evaluating with the same country makes no call. The stored value is the whole response — returnPath applies after the cache.
  • Two timeouts, deliberately different. timeout on the node is a per-request limit whose expiry is an ordinary runtime failure, so the node's own fallback catches it — the network-flakiness guard, applied per node. The timeout option is a hard bound on the whole evaluation; that's rung 09.
  • The fallback is an array because the consumer is a dropdown. Only the author knows both the right placeholder and its type — options degrade to a list, a label to a string. That is exactly why degradation lives in the expression rather than in options.
  • Nulls at the wire follow the target: a JSON body, graphQL.variables and sql bind values carry null through; a URL query parameter or header with a null value has its pair omitted, which gives the optional-filter idiom for free.

Package a pattern

A fragment is a named, parameterised expression registered on the instance — the unit of reuse for config authors who are not writing code.

fragments $params registration-time validation segments-array paths
Registration the body is compiled and validated here, not at first call
const fig = new FigTree({
  operators: [coreOperators, httpOperators()],
  fragments: {
    countryField: {
      description: 'One field from the restcountries record for a country',
      parameters: {
        country: { type: 'string' },                 // required: no default, no required: false
        field: { type: 'string', default: 'region' },
      },
      expression: {
        $http: {
          url: {
            $buildString: [
              'https://restcountries.com/v3.1/name/%1?fields=%2',
              '$params.country',
              '$params.field',
            ],
          },
          returnPath: [0, '$params.field'],           // segments array: numbers index, strings are keys
        },
        fallback: null,
      },
      metadata: { backgroundColor: '#B2E0FF' },       // opaque — the engine never reads it
    },
  },
})
Call sites named arguments only — fragments have no positional form
{
  region: { $countryField: { country: 'New Zealand' } },
  population: { $countryField: { country: '$data.form.country', field: 'population' } },
  capital: {
    fragment: 'countryField',
    parameters: { country: '$data.form.country', field: 'capital' },
    fallback: 'unknown',
  },
}
Result evaluated with { data: { form: { country: 'Fiji' } } }
{
  region: 'Oceania',
  population: 896444,
  capital: ['Suva'],
}
  • Registration is the fragment's parse moment. An unknown operator in the body, an undeclared $params reference, a malformed node, a type-invalid default or a cycle throws from new FigTree() — not from the first evaluation that happens to call it. If registration succeeds, a call can only fail for data-dependent reasons.
  • Arguments are lazy, memoised per call, and evaluated in the caller's scope — parameters: { country: '$vars.c' } reads the caller's vars. The body is sealed: it sees argument results through $params and nothing else. An argument referenced only in a branch that never runs never evaluates.
  • A parameter is required unless it declares a default or required: false — and those are not synonyms. Optional-without-default is coherent: $params.x yields null, exactly like a missing data path, and composes down the same null gradient. A computed default is written in the body with firstOf, since a declared default is a constant, visible to tooling and never evaluated.
  • parameters can also be one node. parameters: '$data.formResponses' hands over the whole arguments object at runtime — a form response or a database row already shaped correctly. Signature checks move to runtime for that mode, and extra keys are ignored.
  • Recursion is banned. A fragment that transitively reaches itself is a registration error, guarded recursion included — FigTree is a config-logic sandbox, and admitting recursion means depth budgets and a halting story.
  • When composition isn't enough, defineOperator() is the other extension point: a custom operator registers through the same operators array into the same namespace and is invoked exactly like a built-in — { $clamp: [x, 0, 100] }. v2's customFunctions tier, and its dynamically-computed function names, are gone. (The operator contract is still Draft.)
09

Run a whole config, safely

The capstone: an ops dashboard evaluated as one config object, checked before it ever sees data, then run in report mode with something genuinely broken — and finally given a deadline it can survive.

validate() mode: 'report' per-hole degradation timeout shielding
The config with one deliberate authoring slip
const dashboard = {
  '//': 'Ops dashboard — evaluated server-side on every page load.',
  meta: { schemaVersion: 3, renderer: 'dash@3.0' },
  header: { $buildString: ['Good %1, %2', '$data.partOfDay'] },
  quota: {
    $round: [{ $multiply: [{ $divide: ['$data.usage.used', '$data.usage.limit'] }, 100] }, 1],
  },
  incidents: {
    $http: { url: 'https://status.example.com/api/incidents', returnPath: 'items[*].title' },
    fallback: [],
  },
}

Beat one — check it before the data exists

fig.validate(dashboard) synchronous, no I/O — an editor can run this at keystroke rate
{
  valid: false,
  issues: [
    {
      severity: 'error',
      code: 'unbound-token',
      path: ['header'],
      operator: 'buildString',
      parameter: 'template',
      message: "Template token '%2' has no substitution — 1 supplied. Did you mean '%1'?",
    },
  ],
  timeoutShielded: false,
}

Beat two — fix the template, then run it against hostile data

Data usage.limit is zero; the status API is down
// header is now: { $buildString: 'Good {{$d.partOfDay}}, {{$d.user.first}}' }

const data = { partOfDay: 'evening', user: { first: 'Ada' }, usage: { used: 812, limit: 0 } }
await fig.evaluate(dashboard, { data, mode: 'report' })
{
  result: {
    meta: { schemaVersion: 3, renderer: 'dash@3.0' },   // constant subtree — returned by identity
    header: 'Good evening, Ada',
    quota: null,                                        // degraded: nothing caught the failure
    incidents: [],                                      // the node's own fallback caught the 503
  },
  errors: [
    FigTreeError {
      code: 'operator-failure',
      operator: 'divide',
      path: ['quota', '$round', 0, '$multiply', 0],     // the failing node, as authored
      holePath: ['quota'],                              // the unit that degraded to null
      message: 'divide – division by zero',
    },
  ],
}
  • Report mode never throws, and degradation is per hole. Each maximal evaluable node in the config degrades independently — header and incidents are untouched by quota's failure, and the constant meta subtree never entered the evaluation at all.
  • incidents produced no error. Its fallback caught the 503, which is the path the author designed; only uncaught failures are reported. Caught fallbacks are visible through trace: true, which is the channel for "what actually happened".
  • Two paths per error. path points at the node that failed, deep inside the expression as authored; holePath points at the unit that degraded to null. A failure inside a fragment body carries both ends of that pointer instead — path for the call site, fragment + fragmentPath for the location in the body.
  • errors is in deterministic tree order, not completion order. The same call in throw mode would reject with whichever uncaught failure occurred first — and discard the three healthy values along with it.

Beat three — give every hole a static fallback

The shielded config
const dashboard = {
  '//': 'Ops dashboard — evaluated server-side on every page load.',
  meta: { schemaVersion: 3, renderer: 'dash@3.0' },
  header: { $buildString: 'Good {{$d.partOfDay}}, {{$d.user.first}}', fallback: 'Welcome' },
  quota: { $round: [{ $multiply: [{ $divide: […] }, 100] }, 1], fallback: null },
  incidents: { $http: { … }, fallback: [] },
}
Badge, then a deadline it survives
fig.validate(dashboard)
// → { valid: true, issues: [], timeoutShielded: true }

await fig.evaluate(dashboard, { data, timeout: 50 })
// returns — in THROW mode, without throwing:
// { meta: {…}, header: 'Good evening, Ada', quota: null, incidents: [] }
  • An expression is timeout-shielded iff every hole carries a statically constant fallback. On the deadline, holes that finished contribute their real values, unfinished holes contribute their static fallbacks, and the constant skeleton is spliced around them. No expression work of any kind runs past the deadline, so the bound holds exactly.
  • Shielding is all-or-nothing per expression, precisely so that validate() can badge it. Unshielded, a timeout throws regardless of how many holes happened to finish.
  • The badge is the mitigation for a real hazard. Shielding rides constancy, which is not visually obvious: editing one static fallback into '$data.cachedQuota' silently un-shields the whole expression, because a dynamic fallback could start new work past the deadline. It still catches ordinary runtime failures — it just can't shield the kill switch. Watch for timeoutShielded flipping to false.
  • signal is never shaped by a fallback. A timeout is the expression's problem to degrade around; an abort means the caller cancelled and nobody is waiting.
  • validate() warms the parse cache as a side effect, so a host that validates at config-save time gets its first evaluate() pre-parsed for free. There is no public parse or compile method — this is the only pre-warm anyone needs.

Reference

The grammar in one screen

Reference namespaces

$data · $d
merged evaluation data; missing → null
$vars · $v
nearest enclosing vars block
$params · $p
this fragment's arguments
$element · $e
innermost iterator's current element
$index · $i
its position, zero-based, bare only
  • A string is a reference only if it starts with a namespace token. "$database" is data; "Hello $data.name" is data.
  • Recognised once, at parse. A string arriving from data or an API is never re-read as a reference.

Node kinds

  • Operator node — has an operator key, a literal string.
  • Fragment call — has a fragment key; arguments only in parameters.
  • Shorthand node — exactly one recognised $name key, plus reserved siblings.
  • literal node — a parse boundary; contents are never walked, validated or evaluated.
  • Plain literal — everything else. Reserved keys alone do not make an object a node.

The seven reserved keys

  • operator · fragment · parameters — what to invoke, and with what.
  • fallback — a full expression, lazy, evaluated once, on failure only.
  • useCache — a literal boolean; the lookup happens before evaluation.
  • vars — a structural map of static names to expressions.
  • // — a comment; any value, stripped at parse.
