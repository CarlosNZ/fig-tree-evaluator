## Constructor

`new FigTree(options?)`, and its type parameter.

## `evaluate()`

Evaluate an expression, with per-call options. Returns the result, or `{ result, trace }` under `trace`.

## `compile()`

Compile an expression once, for repeated evaluation. Returns a `CompiledExpression`.

## `validate()`

Check an expression without evaluating it.

{/* NOTE (from Checking expressions): the sample-data check (`validate(expression, { data })`) warns at each place a missing path is read, so a path read three times gives three warnings; a read inside a fragment body is reported at the call, naming the fragment. The data is used for this check only: nothing is evaluated. Issue order: the size-limit errors first, then the expression's own issues in tree order, then the sample-data warnings. */}

## `getDependencies()`

What an expression reads.

## `isEvaluable()`

Whether an expression holds anything to evaluate.

## `updateOptions()`

Merge an update into the instance's options.

## `with()`

A new instance with an update applied.

## `getOptions()`

The instance's evaluation options.

## `getOperators()` and `getFragments()`

The registered operators and fragments, as plain data.

{/* NOTE (from Fragments): `getFragments()` reports each registered fragment, without its body: `name`, `description`, `metadata` exactly as written, its `parameters` with `required` and any `default` filled in, `returns` (inferred at registration from the body's root), `dependencies` (what the body reads and calls, rolled up through nested calls), `caches`, and `warnings`. The warnings matter most: they're the body's warning-severity issues from registration, which nothing else reports, since registration throws only on errors and a calling expression's `validate()` never repeats a body's warnings. `samples` is never reported. Types: `FragmentInfo` in src/introspect.ts. The Fragments page doesn't mention `getFragments()`, so its "Fragments in an editor" section has no link here; Tooling's "Introspection on the instance" is the other place it's planned. */}

## `clearCache()`

Empty the result store.
