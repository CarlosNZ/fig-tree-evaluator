## `strictDataPaths`

{/* NOTE (from Data references): the option covers drilling into every namespace, not only `$data`: a miss inside `$vars`, `$element` or `$params` fails too, but a miss inside `$error` is always `null`. A `[*]` projection still gives `null` for an element where the rest of the path is missing. A `get` with a `default` (even `default: null`) is the per-place opt-out, and `firstNonNull` can't fill a gap under it, since the reference fails first. The failure's code is `missing-data-path`. It's instance-only, never per call: a host with both kinds of data keeps a strict copy made with `fig.with({ strictDataPaths: true })`, which shares the registry and compile cache (#252). */}

## `maxDepth` and `maxNodes`

{/* NOTE (from Setting up FigTree): say precisely what each counts. `maxDepth` is the expression's nesting depth with plain objects and arrays included, not only nodes: `{ a: { b: { c: { d: 1 } } } }` measures 4. `maxNodes` counts evaluable nodes only: operators, fragment calls and references (so `'$data.x'` counts), never constants or plain containers, and nothing inside `literal`. Both count through fragment calls: `maxNodes` adds a fragment body's count at each call site (two calls count it twice), while `maxDepth` takes the deepest path through the call. Both are checked before anything runs, and also by `validate()` (codes `max-depth` and `max-nodes`). Neither has a default. Source: "Counts" in docs-dev/v3-specs/v3-artifact-obligations.md, and src/validation.ts. */}

## Merge rules

How an update or a per-call option combines with what's already set, and removing a value with `null`.

{/* NOTE (from Setting up FigTree): state the merge rules explicitly, with examples. `updateOptions()` and `with()` merge by key at the top level, and again one level down inside `http`, `graphQL`, `cache`, `fragments` and `operatorDefaults`; anything deeper replaces whole. So `http: { headers: {…} }` keeps `baseEndpoint` but replaces the whole `headers` object (an `X-App` header set earlier is gone), and `operatorDefaults: { join: {…} }` replaces `join`'s whole entry while other operators' entries stay. Arrays always replace, as do `data` and `operators`. `null` removes a value at either level (`{ timeout: null }`, `{ http: { baseEndpoint: null } }`), but deeper down it's a value: `operatorDefaults: { join: { fallback: null } }` sets a null fallback. `undefined` is ignored. Per-call options never merge: each replaces the instance's value for that call, `data` included. Setting up FigTree ("Changing options") describes the merge only loosely ("options that hold a set of entries … merged in one at a time"), so link back there. The rule table is in "Merge semantics" in docs-dev/v3-specs/v3-api.md. */}
