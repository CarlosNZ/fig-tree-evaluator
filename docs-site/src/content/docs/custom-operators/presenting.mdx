Information _about_ your operator, such as full descriptions, display colours and extended metadata, doesn't belong in the operator definition, as the FigTree runtime has no use for it — it would just bloat the bundle. However, to incorporate operators into external tools, like a visual editor or documentation generator, you can provide a **listing** to package this data in standardised form.

## Writing a listing

A listing is plain data. Here's one for the `formatNumber` operator from [Writing an operator](/custom-operators/writing/#a-first-operator):

```ts title="formatNumberListing.ts"
import type { Listing } from 'fig-tree-evaluator'

export const formatNumberListing: Listing = {
  displayName: 'Format number',
  description: "Format a number with a locale's digit grouping and decimal mark",
  parameterDescriptions: {
    value: 'The number to format',
    locale: "The locale to format for, such as 'de-DE' or 'en-IN'",
  },
  docUrl: 'https://wiki.example.com/operators/format-number',
  colors: { background: '#f6d4b0', text: '#3f2f18' },
  // A string parameter otherwise starts as 'Replace me', which
  // isn't a locale
  seeds: { locale: 'de-DE' },
  samples: { value: 83200000, locale: 'en-IN' },
  // A key of your own
  metadata: { owner: 'reporting-team' },
}
```

Every field is optional, and the [catalog](#joining-listings-to-an-instance) fills in what it can where one is missing, such as the operator's name for `displayName`. Give the ones your tools use:

- **Info:**
  - **`displayName`**: a label for menus and node headers.
  - **`description`**: what the operator does.
  - **`parameterDescriptions`**: an explanation of each parameter, by name.
  - **`docUrl`**: a link to the operator's documentation.
- **Colours:**
  - **`colors`**: the CSS colours to draw the operator's nodes in, as a `background` and the `text` on it. Nothing checks the contrast, so we recommend text at 4.5:1 or better against its background ([WCAG AA](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)), as the core operators' listings have.
- **For an editor:**
  - **`seeds`**: what each parameter _starts as_ when someone adds it, by name. A parameter without a seed starts from a generic value for its type ([Type seeds](/tooling/catalog/#type-seeds)), such as `'Replace me'` for a string or `1` for a number, so a more context-appropriate seed guides someone using the editor.
  - **`samples`**: _realistic_ values for each parameter, by name, for a tool to run the operator with, such as a panel for trying it out, a test, or its documentation.
- **Your own:**
  - **`metadata`**: a plain object with anything you like in it, for your own tools. FigTree never reads it. A [definition can have `metadata`](/custom-operators/writing/#the-definition) too, and the two are merged in the catalog, so data for your external tools goes in the listing, and data your app uses while it runs goes on the definition.

<Callout kind="tip" title="A seed is not a default">
  A seed is what an editor fills in when someone _adds_ the parameter. The definition's `default` is what applies when they _leave it out_. A parameter is usually added to change it from its default, so a seed of `'en-NZ'` for `locale` (its default) would add a parameter that does nothing.
</Callout>

## Joining listings to an instance

Listings are made available to external tools via the **catalog**, which is generated by `getCatalog()`, from the `fig-tree-evaluator/catalog` subpath. The structure returned contains a list of all available operators with their definition and listings combined.

Call `getCatalog()` with a FigTree instance, and a map of your listings, keyed by operator name, in its `listings` option. (Listings for the built-in operators are included automatically.)

```ts title="catalog.ts"
// @filename: operators/formatNumber.ts
import type { ValidatedOperatorDefinition } from 'fig-tree-evaluator'
export declare const formatNumber: ValidatedOperatorDefinition
// @filename: operators/formatNumberListing.ts
import type { Listing } from 'fig-tree-evaluator'
export declare const formatNumberListing: Listing
// @filename: catalog.ts
// ---cut---
import { FigTree, coreOperators } from 'fig-tree-evaluator'
import { getCatalog } from 'fig-tree-evaluator/catalog'
import { formatNumber } from './operators/formatNumber'
import { formatNumberListing } from './operators/formatNumberListing'

const fig = new FigTree({ operators: [coreOperators, formatNumber] })

const catalog = getCatalog(fig, {
  // Or an ARRAY of these maps, each merged over the ones before it
  listings: { formatNumber: formatNumberListing },
})
```

Here's the `formatNumber` entry in the catalog, with the listing combined with what FigTree reports about the operator:

```json5
{
  name: 'formatNumber',
  category: 'string',
  restParam: null,
  timeoutParam: null,
  cache: false,
  returns: 'string',
  hasValidate: false,
  positionalParams: ['value', 'locale'],
  displayName: 'Format number',
  colors: { background: '#f6d4b0', text: '#3f2f18' },
  metadata: { owner: 'reporting-team' },
  description: "Format a number with a locale's digit grouping and decimal mark",
  docUrl: 'https://wiki.example.com/operators/format-number',
  parameters: {
    value: {
      type: ['number', 'null'],
      required: true,
      evaluationMode: 'eager',
      truthiness: false,
      nullPolicy: 'propagate',
      nullBehavior: 'propagate',
      seed: 1, // No seed in the listing, so the generic one for a number
      description: 'The number to format',
      sample: 83200000,
    },
    locale: {
      type: 'string',
      required: false,
      evaluationMode: 'eager',
      truthiness: false,
      default: 'en-NZ',
      nullBehavior: 'omit', // No nullPolicy, since the type has no null
      seed: 'de-DE',
      description: "The locale to format for, such as 'de-DE' or 'en-IN'",
      sample: 'en-IN',
    },
  },
}
```

What each field means is covered under [`getCatalog()`](/tooling/catalog/#getcatalog).

<Callout kind="note" title="Fragments have listings too">
  A fragment's listing is the same type. It can go on the fragment's definition, since a fragment is data your app loads anyway ([Fragments in an editor](/guides/fragments/#fragments-in-an-editor)), or in a map in `listings`, as an operator's does. Where a fragment has both, the map's is merged over the definition's.
</Callout>
