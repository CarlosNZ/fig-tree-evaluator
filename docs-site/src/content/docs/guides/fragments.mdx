## What a fragment is

A named expression registered on the instance and called with a `$` key, like an operator.

## Defining a fragment

The `fragments` option: each fragment's `expression`, `parameters` and `description`.

## Parameters

Declaring parameters, passing arguments, and reading them in the body with `$params.`.

{/* NOTE (from Iteration): a fragment called inside an iterator's `each` doesn't see `$element` / `$index` (or `as` names) — fragments are sealed, the same rule as the caller's `vars`. Pass them as parameters: `parameters: { user: '$element' }`. */}

## Calling a fragment

The call node's forms, and how a call is checked against the fragment's parameters.

## Registering and updating

Fragments are set at construction or with `updateOptions()`, never per call, and an update merges with the existing set.

{/* NOTE (from Checking expressions): checking a fragment body before registering it, as a fragment editor does. `validate(body, { params: ['country', 'amount'] })` checks the body as registration would, with its `$params` references resolved against those names: an undeclared one is `unresolved-param` ("the fragment declares no parameter 'z'"), and `params: []` is a body that declares nothing. Without `params`, every `$params` reference is the outside-a-body error. It's `validate()`-only: `evaluate()` and `compile()` refuse it. `getDependencies(body).params` gives `{ names, dynamic }`, the parameter names the body reads (the first key of each path: `$params.country.code` reads `country`), for adding a declaration for each; it doesn't follow calls into other fragments' bodies. Registration still throws for anything wrong with the declarations themselves. */}
