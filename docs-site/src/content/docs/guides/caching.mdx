## Compiling once

`compile()` for an expression evaluated many times: the `CompiledExpression` it returns, and when holding one beats letting `evaluate()` find it in the compile cache.

## Two caches

The compile cache, which holds each expression's compiled form, and the result cache, which holds the results of operators whose definitions ask for it (the I/O operators among them).

## The `cache` option

`maxSize` and `maxTime`, and passing your own `store`.

## Turning caching off

`noCache` on a node, or for every use of an operator through `operatorDefaults` (links to Setting up FigTree).

## Clearing the cache

`clearCache()` empties the result cache, never the compile cache. An instance made with `with()` shares the original's compile cache but has a result cache of its own, so clearing one doesn't touch the other.

## A shared store

The `CacheStore` interface, for a cache that outlives the process or is shared between instances.
