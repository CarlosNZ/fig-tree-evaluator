## Creating an instance

`new FigTree(options)`. With no options, an instance has the core operators and nothing else.

## Instance options and per-call options

One option shape in two places: on the instance, and as `evaluate()`'s second argument, merged over the instance's for that call.

## Changing options

`updateOptions()` merges an update into the instance; `with()` returns a new instance with the update applied and leaves the original as it was. Passing `null` removes a stored value.

## Choosing operators

The `operators` option. Omitted, it is `coreOperators`; given, it lists the whole registry, so a host can leave operators out (such as the I/O operators, for expressions from a source that shouldn't reach the network) or add its own. Links to Custom operators and to HTTP and SQL.

## Defaults for an operator

`operatorDefaults`: constant values for an operator's optional parameters, a static `fallback` (a constant, or one that reads only `$error`) or `noCache`, applied to every use of that operator. A node's own values override them, except `noCache`, which nothing turns back on. Fallbacks and errors and Caching link here.

## Limits

`maxDepth`, `maxNodes`, and the evaluation-wide `timeout` and `signal`, for expressions from sources you don't fully control. The `timeout` is a deadline for the whole evaluation, fallbacks included, and has no default. Links to Guarantees for why an evaluation is bounded.
