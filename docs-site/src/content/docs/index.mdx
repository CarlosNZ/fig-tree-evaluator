FigTree lets you put real logic in places that can only hold data, like a config file, a database row or a form definition. Here's a form field that shows only for licensed drivers aged 16 or over, with help text that names the user's country. Change the data, or the expression, and watch the result follow:

<Playground
  client:visible
  id="example"
  expression={`
    {
      label: 'Driver licence number',
      type: 'text',
      // A $-prefixed key runs an operator
      visible: {
        // A '$data.…' string reads a value
        $and: [{ '$>=': ['$data.age', 16] }, '$data.hasLicence'],
      },
      helpText: {
        $buildString: 'Required for drivers in {{$data.country}}',
      },
    }
  `}
  data={`
    { age: 34, hasLicence: true, country: 'New Zealand' }
  `}
/>

That ran in your browser, through FigTree itself. Every example on this site is evaluated for real.

## Why FigTree?

<CardGrid>
  <Card title="Sandboxed" icon="padlock">
    An expression is JSON in and JSON out. It can only use the operators you register, so nothing in
    it can execute code.
  </Card>
  <Card title="Strict, then forgiving" icon="approve-check-circle">
    Unknown operators and malformed parameters are caught before anything runs. At runtime, any node
    can carry a `fallback` for bad data or a failed lookup.
  </Card>
  <Card title="Lookups through your clients" icon="database">
    HTTP, GraphQL and SQL operators use a client you pass in, so nothing you don't use ends up in
    your bundle.
  </Card>
  <Card title="Built to extend" icon="puzzle">
    Write fully typed custom operators, reuse logic as named fragments, and drop a visual editor into
    your own app.
  </Card>
</CardGrid>

It's a good fit wherever rules change more often than code: eligibility and pricing rules, feature-flag targeting, workflow conditions, and message templates whose sections depend on the recipient.

## Quick start

<Tabs syncKey="pkg">
  <TabItem label="pnpm">
    ```sh
    pnpm add fig-tree-evaluator
    ```
  </TabItem>
  <TabItem label="npm">
    ```sh
    npm install fig-tree-evaluator
    ```
  </TabItem>
  <TabItem label="yarn">
    ```sh
    yarn add fig-tree-evaluator
    ```
  </TabItem>
</Tabs>

```ts twoslash
import { FigTree } from 'fig-tree-evaluator'

const fig = new FigTree()

const visible = await fig.evaluate(
  { '$>=': ['$data.age', 16] }, // the expression
  { data: { age: 34 } } // the data it reads
)
// → true
```

FigTree is ESM-only, written in TypeScript with its types included, and needs Node 22.12 or later (or any modern browser).
