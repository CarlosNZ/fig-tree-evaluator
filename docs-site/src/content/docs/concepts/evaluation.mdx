## Checked first, then run

An expression is read and checked once, before any of it runs: operator names, the shape of each node, parameter names, and `$vars` names in scope. Mistakes found here are errors in the expression, reported all at once, and no `fallback` catches them; failures while running (bad data, a lookup that fails) are what fallbacks are for. A checked expression is reused, so evaluating it again is cheap. Links to [Checking expressions](/guides/validation/), "Evaluating the same expression often" in [Setting up FigTree](/guides/setup/), and [Compile, check, evaluate](/under-the-hood/model/).

## Recursive and asynchronous

Children are evaluated before their parent, and evaluation is always async.

## Parameters an operator evaluates itself

Branching operators such as `if` evaluate only the branch they take.

## Types and nulls

The engine checks each parameter's type before the operator runs, and applies the operator's null policy.

## When evaluation fails

Errors stop evaluation unless a fallback catches them. A short summary, linking to the fallbacks and errors guide.
