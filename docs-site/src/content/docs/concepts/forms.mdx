The examples on this site are written in _shorthand_ — using `$`-prefixed keys for operators. Each node also has a _canonical_ form (the playgrounds call it _full_), which drops the `$` prefix in favour of an `operator` key, and keeps the parameters in the node alongside it, as in:

```json5
{
  operator: 'plus',
  values: [4, 5, 6],
} // => 15
```

You won't need it when writing expressions by hand, but it's useful when, for example:

- **You're building a tool, such as a visual editor:** each object in the JSON is exactly one node of the underlying [expression tree](/concepts/expressions/#nodes-inside-nodes-the-tree), so it maps cleanly onto the UI components that represent the tree.[^internal]
- **Expressions are stored where `$` keys can't go,** such as Firebase, which rejects them, or MongoDB, where they clash with its own query operators.

Both forms mean exactly the same thing, and you can [convert](#converting) from one to the other at any time.

```json5
// Shorthand, with positional parameters
{
  $if: [
    '$data.isLoggedIn',
    { $buildString: ['Hello, %1!', '$data.firstName'] },
    'Welcome, guest!',
  ],
}

// is the same as shorthand, with named parameters
{
  $if: {
    condition: '$data.isLoggedIn',
    then: {
      $buildString: {
        template: 'Hello, %1!',
        substitutions: ['$data.firstName'],
      },
    },
    else: 'Welcome, guest!',
  },
}

// is the same as canonical
{
  operator: 'if',
  condition: '$data.isLoggedIn',
  then: {
    operator: 'buildString',
    template: 'Hello, %1!',
    substitutions: ['$data.firstName'],
  },
  else: 'Welcome, guest!',
}

// You can mix and match freely
{
  operator: 'if',
  condition: '$data.isLoggedIn',
  then: { $buildString: ['Hello, %1!', '$data.firstName'] },
  else: 'Welcome, guest!',
}
```

## The canonical form

Modifiers go in the same object too, which is where the two forms differ most. Shorthand puts the parameters inside the value of the `$`-prefixed key, and the modifiers beside it:

<Expression
  code={`
    {
      shorthand: {
        $divide: { value: '$data.totalSpend', by: '$data.orderCount' },
        fallback: 0, // BESIDE $divide, not inside it
      },
      canonical: {
        operator: 'divide',
        value: '$data.totalSpend',
        by: '$data.orderCount',
        fallback: 0, // All on one level
      },
    }
  `}
  data={`
    // A new customer, with no orders yet
    { totalSpend: 0, orderCount: 0 }
  `}
/>

<Callout kind="note" title="Data with an operator key">
  Like a key prefixed with `$`, an `operator` key is read as a node wherever it appears, whichever form you write in, so data with one of its own goes inside `literal` ([Operators](/concepts/expressions/#operators)).
</Callout>

## Converting

In the playgrounds on this site, the **Shorthand** and **Full** buttons rewrite the whole expression in one form. Try them on this one:

<Playground

    {
      operator: 'if',
      condition: { '$>=': ['$data.order.subtotal', 100] },
      then: 0,
      else: {
        operator: 'plus',
        values: [5, { $multiply: ['$data.order.weightKg', 1.5] }],
      },
    }
  `}
  data={`
    { order: { subtotal: 72, weightKg: 2 } }
  `}
/>

References such as `$data.order.subtotal` stay as they are in both forms. Their long form is a [`get` node](/concepts/data/#the-get-operator), which the editor converts one at a time.

In your own code, `toCanonical` and `toShorthand` do the same. Each takes your FigTree instance too, since how a node is read depends on which operators it has, and the order of their parameters:

```ts
import { toCanonical, toShorthand } from 'fig-tree-evaluator/format'

const full = toCanonical({ $plus: [1, 2, 3] }, fig)
// => { operator: 'plus', values: [1, 2, 3] }

toShorthand(full, fig) // => { $plus: [1, 2, 3] }
```

[Converting forms](/tooling/format/) has their options, such as named parameters rather than positional ones.

[^internal]: In fact, this is close to the structure FigTree compiles an expression into internally, whichever form it was written in: one object per node, with its parameters by name, plus what the engine needs to run it ([Compile, check, evaluate](/under-the-hood/model/#compile)).
