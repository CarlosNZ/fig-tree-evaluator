## No code runs

An expression can only call registered operators. There is no way to execute code from an expression.

## Data is never evaluated

A value that arrives at runtime, from the data, a request or a query, is never read as an expression. A string that looks like a reference is just a string. Example: data holding `'$data.password'`, returned as text.

## The input is never modified

Neither the expression nor the data is written to. Results may share structure with them.

## Checking never throws on content

However malformed an expression, checking it reports every problem as an issue rather than stopping at the first. `validate()` throws only for invalid options.

## A branch not taken never runs

A lazy parameter that isn't needed is never evaluated: an `if`'s other branch, a fallback when nothing failed, the rest of an `and` once one value is false. Its requests aren't sent, and its failures can't happen.

## A variable is computed at most once

Each variable runs on its first read, once per evaluation, and not at all if nothing reads it. Branches running at the same time that read it share the one run.

## Evaluation is bounded

`maxDepth`, `maxNodes` and `timeout` put limits on what any expression can cost. The language has no recursion (a fragment can't call itself) and no open-ended loops: iteration runs over arrays that already exist.

## What FigTree asks of the host

The two rules on the host's side: don't change a result, since it can share structure with the expression, the data and cached results; and don't change an expression after evaluating it, since the compile cache knows it by the object.
