The core FigTree package keeps things tight — it holds only what you need to set up FigTree and evaluate expressions. Tools for working _with_ expressions, such as [getting an instance's operator and fragment listings](/tooling/catalog/), [converting between expression forms](/tooling/format/), or [checking fallback coverage](/tooling/authoring/), are in separate subpaths, each with its own import path. They're what the [visual editor](/editor/) is built on.

## The subpaths

### `fig-tree-evaluator/catalog`

The **catalog** is every operator and fragment an instance has, each reported with its declaration plus how to _present_ it, such as a display name, a description, colours, and starting values for its parameters. `getCatalog()` builds it from the instance, adding the listings for the built-in operators that come with `/catalog`, and any you've written for your custom ones ([Presenting your operator](/custom-operators/presenting/)):

```ts title="catalog.ts"
import { getCatalog } from 'fig-tree-evaluator/catalog'

const catalog = getCatalog(fig)
const plus = catalog.operators.find((op) => op.name === 'plus')

plus?.displayName // => 'Plus (+)'
plus?.colors // => { background: '#d7edd4', text: '#193e1e' }
```

The [`/catalog`](/tooling/catalog/) page covers the whole of what `getCatalog()` returns, and how to change how operators are presented.

### `fig-tree-evaluator/format`

We've already met this subpath's functions for [converting between expression forms](/concepts/forms/#converting). It also has functions for things such as classifying parts of an expression tree or recognising reference strings, the same way FigTree does internally:

```ts title="format.ts"
import { recognizeReference } from 'fig-tree-evaluator/format'

recognizeReference('$data.user.name')
// => {
//      kind: 'reference',
//      namespace: 'data',
//      segments: ['user', 'name'],
//      drill: '.user.name',
//    }
recognizeReference('$5.00') // => { kind: 'unrecognized' }
```

The [`/format`](/tooling/format/) page covers every function in the subpath, with their options.

### `fig-tree-evaluator/authoring`

`fallbackCoverage()` checks an expression before it runs, finding every way each node can fail, and which fallback, if any, catches each failure:

```ts title="coverage.ts"
import { fallbackCoverage } from 'fig-tree-evaluator/authoring'

const report = await fallbackCoverage(fig, {
  $divide: ['$data.total', '$data.count'],
})

report.uncovered.map(({ code, parameter }) => `${code} at ${parameter}`)
// => ['type-check at value', 'type-check at by', 'non-finite-result at by']
```

The [`/authoring`](/tooling/authoring/) page covers reading the report.

The fourth subpath, `fig-tree-evaluator/migrate`, converts v2 expressions to v3, and is covered in [Migrating from v2](/migrating/).

## Instance introspection

`getOperators()` and `getFragments()` need no subpath — they're methods on the FigTree instance, and just return plain data about the registered operators and fragments. For each operator, that's its declaration as the instance uses it, with every default filled in:

```ts title="operators.ts"
const divide = fig.getOperators().find((op) => op.name === 'divide')
```

Here's what it returns for `divide`:

```json5
{
  name: 'divide',
  alias: '/',
  category: 'math',
  parameters: {
    value: {
      type: ['number', 'null'],
      required: true,
      evaluationMode: 'eager',
      truthiness: false,
      nullPolicy: 'propagate',
      nullBehavior: 'propagate',
    },
    by: {
      type: ['number', 'null'],
      required: true,
      evaluationMode: 'eager',
      truthiness: false,
      nullPolicy: 'propagate',
      nullBehavior: 'propagate',
    },
  },
  positionalParams: ['value', 'by'],
  restParam: null,
  timeoutParam: null,
  cache: false,
  returns: 'number',
  hasValidate: false,
}
```

`getFragments()` gives the same for each fragment, without its body. `getCatalog()` calls both methods for the declarations in the catalog. The full types are in the [API reference](/api/figtree/#getoperators-and-getfragments).
