You're building something that reads or rewrites FigTree expressions: a visual editor, say, or a layer that stores expressions in canonical form but shows them to people as shorthand. [Shorthand and canonical forms](/concepts/forms/#converting) introduced the functions that convert between the forms. This page has all of them, with their options.

{/* STAND-IN: Carl to rewrite */}
The subpath also exports the functions FigTree's own compiler uses to read an expression, so a tool that walks one itself reads it exactly as FigTree does.

## `toCanonical()` and `toShorthand()`

Each one rewrites every node in an expression into one form, without changing what it means. They take your FigTree instance too, since mapping a positional payload such as `[1, 2]` onto parameters needs each operator's positions, and whether a `$`-prefixed key is an operator or a fragment depends on what's registered:

```ts title="convert.ts"
import { toCanonical, toShorthand } from 'fig-tree-evaluator/format'

const average = {
  $round: [{ $divide: ['$data.totalSpend', '$data.orderCount'], fallback: 0 }, 2],
}

const canonical = toCanonical(average, fig)
toShorthand(canonical, fig) // => the same as average
```

Here's `canonical`:

```json5
{
  operator: 'round',
  value: {
    operator: 'divide',
    value: '$data.totalSpend',
    by: '$data.orderCount',
    fallback: 0,
  },
  decimals: 2,
}
```

Neither function changes the expression you pass it.

The instance is only read for its operators' names, aliases and positions, and its fragments' names, so anything with `getOperators()` and `getFragments()` methods that return those will do. That suits an editor that has no instance of its own, only the operators and fragments a server sent it:

```ts title="registry.ts"
declare const expression: unknown
// ---cut---
import { toShorthand } from 'fig-tree-evaluator/format'

// Sent by the server, from its own fig.getOperators()
// and fig.getFragments()
const { operators, fragments } = await fetch('/api/fig-tree').then((res) => res.json())

toShorthand(expression, {
  getOperators: () => operators,
  getFragments: () => fragments,
})
```

### Options

Both functions take an options object as their third argument:

- **`operatorNames`** and **`referenceNames`**: how operator names and reference namespaces are spelt, where an operator has a symbolic alias, such as `plus` (`+`), and for the namespaces' short forms, such as `$data` (`$d`):
  - **`'preserve'`** (the default): as written.
  - **`'canonical'`**: `plus`, `$data`.
  - **`'alias'`**: `+`, `$d`. An operator with no alias keeps its name.
- **`arguments`** (`toShorthand()` only): `'positional'`, the default, gives a node its values in an array wherever it can, as in `{ $plus: [1, 2] }` ([Positional or named](#positional-or-named)). `'named'` always gives them by name, as in `{ $plus: { values: [1, 2] } }`.
- **`getAsReference`** (`toShorthand()` only): `true` by default, turning each `get` node that has a reference form into one, so `{ operator: 'get', path: 'user.name' }` becomes `'$d.user.name'`. The namespace is spelt `$d` unless `referenceNames` is `'canonical'`, since there's nothing written to preserve. A `get` with a `//` comment keeps its node, so the comment isn't lost.
- **`referencesAsGet`** (`toCanonical()` only): `false` by default, since a reference is just as much at home in canonical form. Set to `true` to turn each reference into its `get` node, so `{ $upper: '$data.user.name' }` becomes `{ operator: 'upper', value: { operator: 'get', path: 'user.name' } }`.
- **`recursive`**: `true` by default. Set to `false` to convert only the node you pass, so `toCanonical(average, fig, { recursive: false })` converts the `$round` and leaves its `$divide` as written. The editor's toolbar on a shorthand node works this way: it converts the node alone to canonical form, to edit it a parameter at a time, then back again, leaving the nodes inside it in whatever form they were written in.

### Positional or named

With `arguments: 'positional'`, `toShorthand()` writes a node's values as an array only where that array reads back as the same node, and by name otherwise. So some nodes come out named, and some keep an array around a single value:

| Node                                                       | Shorthand                                           | Why                                                          |
| ---------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------ |
| `{ operator: 'not', value: '$data.isMember' }`             | `{ $not: '$data.isMember' }`                        | A single value needs no array                                |
| `{ operator: 'if', condition: '$data.isMember', else: 0 }` | `{ $if: { condition: '$data.isMember', else: 0 } }` | `then` is missing, and a position can't be left empty        |
| `{ operator: 'plus', values: [5] }`                        | `{ $plus: [5] }`                                    | `{ $plus: 5 }` would make `values` the number `5`, not an array |
| `{ operator: 'min', values: '$data.scores' }`              | `{ $min: '$data.scores' }`                          | `values` is computed, so it goes in whole                    |

A fragment call always takes its arguments by name, and one whose `parameters` is a reference, such as `{ fragment: 'greet', parameters: '$data.person' }`, stays canonical, since a shorthand fragment call needs an object.

### When a conversion throws

The conversions read an expression as FigTree's compiler does, so a node the compiler can't read stops them. They throw a [`FigTreeError`](/api/errors/#figtreeerror) with the compiler's own code, such as `unknown-operator` or `malformed-node`, and a `path` to the node from wherever the conversion started:

```ts title="throws.ts"
import { toShorthand } from 'fig-tree-evaluator/format'
// ---cut---
toShorthand(
  {
    operator: 'if',
    condition: '$data.isMember',
    then: { operator: 'memberPrice' },
    else: '$data.price',
  },
  fig
)
// Throws a FigTreeError, with code 'unknown-operator' and path ['then']
```

Anything else is left for [`validate()`](/guides/validation/) to find, such as a parameter of the wrong type, or a `$vars` reference with no variable to read. A tool often converts part of an expression on its own, such as the `each` of a `map`, which reads `$element` from the `map` around it, or a node someone is still building, which doesn't have all its parameters yet.

## `toGet()` and `toReference()`

These two convert a single reference to its `get` node, and back. Each returns `null` where its input has no other form, which tells an editor whether to offer the conversion at all, so neither one throws:

```ts title="references.ts"
import { toGet, toReference } from 'fig-tree-evaluator/format'

toGet('$d.user.name') // => { operator: 'get', path: 'user.name' }
toGet('$vars.row.total')
  // => { operator: 'get', path: 'row.total', from: '$vars' }
toGet('$index') // => null, since it's a number, with no path to read
toGet('Kia ora') // => null

toReference({ $get: 'user.name' }) // => '$d.user.name'
toReference({ $get: 'user.name', fallback: 'Guest' }) // => null
```

`toReference()` takes a `get` node in any form, and returns `null` wherever a reference couldn't read the same thing, such as a `get` with a `fallback` or a `default`, which a string has nowhere to put, or one whose path is computed. A `//` comment doesn't stop it, but is dropped.

Both take `referenceNames`, as [`toCanonical()` and `toShorthand()`](#options) do.

Since `toGet()` returns a canonical node, passing it to `toShorthand()` turns it straight back into a reference. To show it as a shorthand `get`, pass `getAsReference: false` as well.

## Reading primitives

{/* STAND-IN: Carl to rewrite */}
A tool that walks an expression itself, such as an editor deciding how to show each part of one, has to read it exactly as FigTree does, or the two will disagree about what's a node and what's data. So rather than leaving you to copy FigTree's rules, `/format` exports the functions its compiler uses. Each one reads a single object or string, and the walk itself, including knowing where in the expression you are, stays your tool's job.

### `classifyObject()`

`classifyObject()` says what an object is, by its keys: an operator node, a fragment call, a shorthand node, plain data, or malformed. Whether a `$`-prefixed key invokes anything depends on what's registered, so you pass it a function that answers that. To agree with FigTree, it should answer `true` for `literal`, every operator's name and alias, and every fragment's name:

```ts title="classify.ts"
import { classifyObject } from 'fig-tree-evaluator/format'

const names = new Set(['literal'])
for (const { name, alias } of fig.getOperators()) {
  names.add(name)
  if (alias !== undefined) names.add(alias)
}
for (const { name } of fig.getFragments()) names.add(name)
const recognizes = (name: string) => names.has(name)

classifyObject({ operator: 'plus', values: [1, 2] }, recognizes) // => { kind: 'operator' }
classifyObject({ $plus: [1, 2], fallback: 0 }, recognizes)
  // => { kind: 'shorthand', key: '$plus' }
classifyObject({ $plus: [1], $multiply: [2] }, recognizes)
  // => { kind: 'malformed', message: "one node, one invocation: …" }
classifyObject({ $plsu: [1, 2] }, recognizes) // => { kind: 'plain' }
```

An object whose only `$`-prefixed key is unrecognised, such as a typo, is plain data, as it is to the compiler, which reports the key as an error when it checks the expression.

### `recognizeReference()`

`recognizeReference()` says whether a string is a reference, and to what. The `kind` in its result is one of:

- **`'reference'`**: a well-formed reference, with its `namespace` (`'data'`, `'vars'`, `'params'`, `'element'`, `'index'` or `'error'`, whichever spelling was used), its path as `segments`, and `drill`, the path's text after the namespace, as written. A tool can use `drill` to respell the namespace without rebuilding the path.
- **`'invalid'`**: a namespace used in a way FigTree rejects, such as `'$index.x'`, with a `reason`, and a `code` where the rule broken has one of its own, such as `bare-vars` for a bare `'$vars'`.
- **`'unrecognized'`**: a string starting with `$` that names no namespace, such as `'$5.00'`, which FigTree reads as plain text.
- **`'plain'`**: a string that doesn't start with `$`.

```ts title="recognize.ts"
import { recognizeReference } from 'fig-tree-evaluator/format'

recognizeReference('$d.items[0].price')
// => {
//      kind: 'reference',
//      namespace: 'data',
//      segments: ['items', 0, 'price'],
//      drill: '.items[0].price',
//    }
recognizeReference('$index.x')
// => {
//      kind: 'invalid',
//      namespace: 'index',
//      reason: "'$index' is bare-only — it cannot be drilled",
//    }
```

An iterator's [`as`](/concepts/iteration/#naming-them-with-as) gives its element a name of its own, such as `$item`, along with `$itemIndex` for its index. Which names are in scope depends on where the string is, which only your walk knows, so pass them in `bindings`. A match carries the `binding` it used:

```ts title="bindings.ts"
import { recognizeReference } from 'fig-tree-evaluator/format'
// ---cut---
recognizeReference('$item.price', { bindings: ['item'] })
// => {
//      kind: 'reference',
//      namespace: 'element',
//      segments: ['price'],
//      drill: '.price',
//      binding: 'item',
//    }
recognizeReference('$item.price') // => { kind: 'unrecognized' }
```

### `positionalLayout()` and `singlePositionalTarget()`

These two say how a positional payload binds to an operator's parameters. They take the operator as [`getOperators()`](/api/figtree/#getoperators-and-getfragments) reports it:

- **`positionalLayout(operator, length)`** takes an array's length, and returns how many leading parameters the array fills (`bound`), and the index where the rest parameter's values start (`restAt`), or `null` if there's no rest. The rest is bound whenever the leading parameters are all filled, even with nothing left over, as an empty array. It returns `null` where an array that long can't bind.
- **`singlePositionalTarget(operator)`** names the parameter a single value, not in an array, fills.

```ts title="positions.ts"
import { positionalLayout, singlePositionalTarget } from 'fig-tree-evaluator/format'

const operators = fig.getOperators()
const buildString = operators.find((op) => op.name === 'buildString')!
const ifOperator = operators.find((op) => op.name === 'if')!

// buildString's positions: ['template', '...substitutions']
positionalLayout(buildString, 3) // => { bound: 1, restAt: 1 }

// if's positions: ['condition', 'then', 'else']
positionalLayout(ifOperator, 2) // => { bound: 2, restAt: null }
positionalLayout(ifOperator, 4) // => null, since if has only three
singlePositionalTarget(ifOperator) // => 'condition'
```

So `{ $buildString: ['Hi %1 %2', '$data.first', '$data.last'] }` binds `template` to the first value, and `substitutions` to the other two.

### `typesIntersect()`

`typesIntersect()` says whether two declared types have any value in common. It's the check behind [`returns-mismatch`](/api/errors/#static-errors), the static error for a node whose result can never fit where it's used. An editor can use it the same way, to offer only the operators whose result could fit where the author is adding one:

```ts title="picker.ts"
import { typesIntersect } from 'fig-tree-evaluator/format'

const operators = fig.getOperators()
const by = operators.find((op) => op.name === 'divide')!.parameters.by

// by takes a number or null, so this includes plus, round and length,
// but not and or upper, which return a boolean and a string
const offered = operators.filter((op) => typesIntersect(op.returns, by.type))
```

The `message` of a malformed object and the `reason` of an invalid reference are written for people, and may change between versions, so a tool shouldn't depend on their text.
