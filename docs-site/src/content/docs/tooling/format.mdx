FigTree expressions can be written in [more than one form](/concepts/forms/), and even the main form (shorthand) has [named, positional and single-value variants](/concepts/expressions/#parameters). The `/format` subpath provides a set of tools for converting between all these forms, such as an editor would use to switch a node from one form to another.

The subpath also exports the functions FigTree's own compiler uses to read an expression.

## `toCanonical()` and `toShorthand()`

These rewrite every node in an expression into the target form, without changing its meaning at all:

```ts title="convert.ts"
import { FigTree } from 'fig-tree-evaluator'
import { toCanonical, toShorthand } from 'fig-tree-evaluator/format'

const fig = new FigTree()

const average = {
  $round: [
    // Values given by name
    { $divide: { value: '$data.totalSpend', by: '$data.orderCount' }, fallback: 0 },
    2,
  ],
}

const canonical = toCanonical(average, fig)
const backAgain = toShorthand(canonical, fig)
```

Here's the `toCanonical()` output:

```json5
{
  operator: 'round',
  value: {
    operator: 'divide',
    value: '$data.totalSpend',
    by: '$data.orderCount',
    fallback: 0,
  },
  decimals: 2,
}
```

And converted back to shorthand:

```json5
{
  $round: [{ $divide: ['$data.totalSpend', '$data.orderCount'], fallback: 0 }, 2],
}
```

Note the `$divide` here has come back in positional form, unlike the original above. The output form can be specified with the `arguments` option, as [described below](#options).

<Callout kind="tip" title="Switching between shorthand forms">
  `toShorthand()` can take a node in _any_ form, so it also switches shorthand between **named** and **positional**: `toShorthand({ $round: { value: '$data.price', decimals: 2 } }, fig)` gives `{ $round: ['$data.price', 2] }`, and with `arguments: 'named'` it goes the other way.
</Callout>

### Options

```ts
import type { FigTree, Spelling } from 'fig-tree-evaluator'
declare namespace Format {
// ---cut---
function toCanonical(
  expression: unknown,
  fig: FigTree,
  options?: {
    operatorNames?: Spelling
    referenceNames?: Spelling
    referencesAsGet?: boolean
    recursive?: boolean
  }
): unknown

function toShorthand(
  expression: unknown,
  fig: FigTree,
  options?: {
    operatorNames?: Spelling
    referenceNames?: Spelling
    arguments?: 'positional' | 'named'
    getAsReference?: boolean
    recursive?: boolean
  }
): unknown
// ---cut-after---
}
```

- **`operatorNames`** and **`referenceNames`**: when rewriting a node, what happens to operator and [reference](/concepts/data/#every-reference) names:
  - **`'preserve'`** (the default): don't change them
  - **`'canonical'`**: e.g. `plus`, `$data`
  - **`'alias'`**: e.g. `+`, `$d` (an operator with no alias keeps its name)
- **`arguments`**: which shorthand form to use ([Positional or named](#positional-or-named)):
  - **`'positional'`** (the default): by position where possible, e.g. `{ $plus: [1, 2] }`
  - **`'named'`**: always by name, e.g. `{ $plus: { values: [1, 2] } }`
- **`getAsReference`**: whether to turn `get` nodes into [references](/concepts/data/#the-get-operator), when converting to shorthand:
  - **`true`** (the default): where possible, e.g. `{ operator: 'get', path: 'user.name' }` becomes `'$d.user.name'`
  - **`false`**: keep them as nodes, e.g. `{ $get: 'user.name' }`
- **`referencesAsGet`**: whether to turn references into `get` nodes, when converting to canonical:
  - **`false`** (the default): leave them, since a reference is just as much at home in canonical form
  - **`true`**: convert them, e.g. `'$data.user.name'` becomes `{ operator: 'get', path: 'user.name' }`
- **`recursive`**: whether to convert all descendant nodes as well:
  - **`true`** (the default): the whole expression
  - **`false`**: only the top-level node

### Positional or named

With `arguments: 'positional'`, `toShorthand()` writes each node in the briefest form that reads back as the same node, based on which parameters it has and the operator's [positional parameters](/custom-operators/writing/#positional-parameters):

- **single value** if only the first positional parameter is given, and its value isn't itself an array or a plain object
- **array** if the parameters given run from the first positional one, with no gaps
- **named** otherwise

For example:

```ts title="positional.ts"
import { toShorthand } from 'fig-tree-evaluator/format'
// ---cut---
// A single value needs no array
toShorthand({ operator: 'buildString', template: 'Hi {{$data.firstName}}' }, fig)
// => { $buildString: 'Hi {{$data.firstName}}' }

// The parameters run from the first positional one, with no gaps
toShorthand(
  {
    $if: {
      condition: '$data.isMember',
      then: 'Member price',
      else: 'Standard price',
    },
  },
  fig
)
// => { $if: ['$data.isMember', 'Member price', 'Standard price'] }

// 'then' is missing, and a position can't be left empty
toShorthand({ operator: 'if', condition: '$data.isMember', else: 0 }, fig)
// => { $if: { condition: '$data.isMember', else: 0 } }

// { $plus: 5 } would make 'values' the number 5, not an array
toShorthand({ operator: 'plus', values: [5] }, fig)
// => { $plus: [5] }

// 'values' is computed, so it goes in whole
toShorthand({ operator: 'min', values: '$data.scores' }, fig)
// => { $min: '$data.scores' }
```

A fragment call always takes its arguments by name, and one whose `parameters` is a reference, such as `{ fragment: 'greet', parameters: '$data.person' }`, stays canonical, since a shorthand fragment call needs an object.

### When a conversion throws

The conversions check only what they need to rewrite each node, such as whether its operator is registered and its positional values fit. Where a node fails those checks, they throw a [`FigTreeError`](/api/errors/#figtreeerror) with a `path` to it, from wherever the conversion started. Anything else, such as a parameter of the wrong type, comes through as written, for [`validate()`](/guides/validation/) to report.

## `toGet()` and `toReference()`

```ts
import type { Spelling } from 'fig-tree-evaluator'
declare namespace Format {
// ---cut---
function toGet(
  reference: unknown,
  options?: { referenceNames?: Spelling }
): Record<string, unknown> | null

function toReference(node: unknown, options?: { referenceNames?: Spelling }): string | null
// ---cut-after---
}
```

These two convert a single reference to its `get` node, and back. Each returns `null` for anything it can't convert, whatever it is, and never throws:

```ts title="references.ts"
import { toGet, toReference } from 'fig-tree-evaluator/format'

toGet('$d.user.name') // => { operator: 'get', path: 'user.name' }
toGet('$vars.row.total')
  // => { operator: 'get', path: 'row.total', from: '$vars' }
toGet('$index') // => null, since it's a number, with no path to read
toGet('Kia ora') // => null

toReference({ $get: 'user.name' }) // => '$d.user.name'
toReference({ $get: { path: 'total', from: '$vars.order' } })
  // => '$vars.order.total'
toReference({ '//': 'Member price', $get: 'price.member' })
  // => '$d.price.member' (⚠️ the comment is dropped)
toReference({
  $get: {
    path: 'NZ',
    from: { NZ: 'New Zealand', AU: 'Australia' },
  },
}) // => null, since it can't be written as a reference
```

<Callout kind="caution" title="Converting a get node to shorthand">

Since `toGet()` returns a canonical node, passing it to `toShorthand()` turns it straight back into a reference. To keep it as a shorthand `get` node, pass `getAsReference: false` as well:

```ts
import { toGet, toShorthand } from 'fig-tree-evaluator/format'
// ---cut---
toShorthand(toGet('$d.user.name'), fig) // => '$d.user.name'
toShorthand(toGet('$d.user.name'), fig, { getAsReference: false })
  // => { $get: 'user.name' }
```

</Callout>

## Reading primitives

A tool that walks an expression, such as an editor deciding how to show each part, should read it exactly as FigTree does, or the two will disagree about what's a FigTree node and what's data. So `/format` exports the functions the compiler uses. Each one answers a single question about one part of an expression — the walk itself stays your tool's job.

### `classifyObject()`

```ts
import type { ObjectClass } from 'fig-tree-evaluator'
declare namespace Format {
// ---cut---
function classifyObject(
  object: Record<string, unknown>,
  recognizes: (name: string) => boolean
): ObjectClass
// ---cut-after---
}
```

`classifyObject()` says what an object is, by its keys: an operator node, a fragment call, a shorthand node, plain data, or malformed. Whether a `$`-prefixed key invokes anything depends on what's registered, so you pass it a function that answers that, built once and reused for every object your tool reads. To agree with FigTree, it should answer `true` for every operator's name and alias, every fragment's name, and `literal`:

```ts title="classify.ts"
import { classifyObject } from 'fig-tree-evaluator/format'

const names = new Set<string>()
for (const { name, alias } of fig.getOperators()) {
  names.add(name)
  if (alias !== undefined) names.add(alias)
}
for (const { name } of fig.getFragments()) names.add(name)
names.add('literal')
const recognizes = (name: string) => names.has(name)

classifyObject({ operator: 'plus', values: [1, 2] }, recognizes)
  // => { kind: 'operator' }
classifyObject({ $plus: [1, 2], fallback: 0 }, recognizes)
  // => { kind: 'shorthand', key: '$plus' }
classifyObject({ $plus: [1], $multiply: [2] }, recognizes)
  // => { kind: 'malformed', message: "one node, one invocation: …" }
classifyObject({ $plsu: [1, 2] }, recognizes)
  // => { kind: 'plain' }, since nothing is registered as 'plsu'
```

### `recognizeReference()`

```ts
import type { ReferenceRecognition } from 'fig-tree-evaluator'
declare namespace Format {
// ---cut---
function recognizeReference(
  value: string,
  scope?: { bindings?: readonly string[] }
): ReferenceRecognition
// ---cut-after---
}
```

`recognizeReference()` says whether a string is a reference, and to what. The `kind` in its result is one of:

- **`'reference'`**: a well-formed reference, with its `namespace` (`'data'`, `'vars'`, `'params'`, `'element'`, `'index'` or `'error'`), its path as `segments`, and `drill`, the path's text after the namespace, as written. (A tool can use `drill` to respell the namespace without rebuilding the path.)
- **`'invalid'`**: a namespace used in a way FigTree rejects, such as `'$index.x'`, with a `reason` for people to read, and a `code` where the rule broken has one of its own, such as `bare-vars` for a bare `'$vars'`.
- **`'unrecognized'`**: a string starting with `$` that names no namespace, such as `'$5.00'`, which FigTree reads as plain text.
- **`'plain'`**: a string that doesn't start with `$`.

```ts title="recognize.ts"
import { recognizeReference } from 'fig-tree-evaluator/format'

recognizeReference('$d.items[0].price')
// => {
//      kind: 'reference',
//      namespace: 'data',
//      segments: ['items', 0, 'price'],
//      drill: '.items[0].price',
//    }
recognizeReference('$index.x')
// => {
//      kind: 'invalid',
//      namespace: 'index',
//      reason: "'$index' is bare-only — it cannot be drilled",
//    }
```

An iterator's [`as`](/concepts/iteration/#naming-them-with-as) gives its element a name of its own, such as `$item`, along with `$itemIndex` for its index. Which names are in scope depends on where the string is, which only your walk knows, so pass them in `bindings`. A match carries the `binding` it used:

```ts title="bindings.ts"
import { recognizeReference } from 'fig-tree-evaluator/format'
// ---cut---
recognizeReference('$item.price', { bindings: ['item'] })
// => {
//      kind: 'reference',
//      namespace: 'element',
//      segments: ['price'],
//      drill: '.price',
//      binding: 'item',
//    }
recognizeReference('$item.price') // => { kind: 'unrecognized' }
```

### `positionalLayout()` and `singlePositionalTarget()`

```ts
declare namespace Format {
// ---cut---
function positionalLayout(
  operator: { positionalParams?: readonly string[]; restParam: string | null },
  length: number
): { bound: number; restAt: number | null } | null

function singlePositionalTarget(operator: {
  positionalParams?: readonly string[]
  restParam: string | null
}): string | null
// ---cut-after---
}
```

For most operators, matching values to the operator's [`positionalParams`](/custom-operators/writing/#positional-parameters) by index is enough. These two cover the cases where it isn't, using FigTree's own rules, so your tool reads a positional payload exactly as the compiler does. Pass each the operator as [`getOperators()`](/api/figtree/#getoperators-and-getfragments) reports it:

- **`positionalLayout(operator, length)`**: takes the number of values in a positional array, such as 3 for `['Hi %1 %2', '$data.first', '$data.last']`, and returns how many of them fill the leading parameters (`bound`), and the index where the rest parameter takes the remaining values (`restAt`, or `null` if there's no rest parameter).[^layout] Once the leading parameters are filled, the rest parameter is always set, to an empty array if nothing is left over. It returns `null` if the array is too long for the operator.
- **`singlePositionalTarget(operator)`**: the parameter a single value goes to, when it isn't in an array. That's normally the first positional parameter. But where the first _is_ the rest parameter, as for `min`, the value becomes the whole rest parameter, so `{ $min: '$data.scores' }` sets `values` to that array.

```ts title="positions.ts"
import { positionalLayout, singlePositionalTarget } from 'fig-tree-evaluator/format'

const operators = fig.getOperators()
const buildString = operators.find((op) => op.name === 'buildString')!
const ifOperator = operators.find((op) => op.name === 'if')!
const round = operators.find((op) => op.name === 'round')!
const min = operators.find((op) => op.name === 'min')!

// buildString's positions: ['template', '...substitutions']
positionalLayout(buildString, 3) // => { bound: 1, restAt: 1 }

// if's positions: ['condition', 'then', 'else']
positionalLayout(ifOperator, 2) // => { bound: 2, restAt: null }
positionalLayout(ifOperator, 4) // => null, since if has only three

// round's positions: ['value', 'decimals']
singlePositionalTarget(round) // => 'value', as in { $round: 3.14159 }

// min's positions: ['...values']
singlePositionalTarget(min) // => 'values'
```

### `typesIntersect()`

```ts
import type { ExpectedType } from 'fig-tree-evaluator'
declare namespace Format {
// ---cut---
function typesIntersect(a: ExpectedType, b: ExpectedType): boolean
// ---cut-after---
}
```

`typesIntersect()` says whether two declared types have any value in common. It's the check behind [`returns-mismatch`](/api/errors/#static-errors), the static error for a node whose result can never fit as input into a parent node:

```ts title="picker.ts"
import { typesIntersect } from 'fig-tree-evaluator/format'

const operators = fig.getOperators()
const by = operators.find((op) => op.name === 'divide')!.parameters.by
const plus = operators.find((op) => op.name === 'plus')!
const upper = operators.find((op) => op.name === 'upper')!

by.type // => ['number', 'null']
plus.returns // => ['number', 'string', 'array', 'object']
upper.returns // => 'string'

typesIntersect(plus.returns, by.type) // => true, since both include 'number'
typesIntersect(upper.returns, by.type) // => false

// So an editor can offer only the operators whose result could fit
// divide's 'by'
const offered = operators.filter((op) => typesIntersect(op.returns, by.type))
```

[^layout]: It returns positions rather than the parameters by name, since a tool working on the array as written, such as an editor labelling each value, needs each value's index to put an edit back in the right place. To get a node's parameters by name, convert it with `toCanonical(node, fig, { recursive: false })`. The logic is short, but using the compiler's own means your tool agrees with FigTree on the edge cases, such as an empty rest parameter or an array that's too long.
