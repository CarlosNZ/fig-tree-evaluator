# FigTree v3 — the compile artifact: obligations checklist

_Chunk-3.1 deliverable (implementation plan, Phase 3). This checklist consolidates every obligation the specs place on the parse/compile artifact, each with its source. **The checklist is the contract; the internal types in [src/parse/artifact.ts](../../src/parse/artifact.ts) are freely refactorable against it** — no test or later phase may depend on the artifact's field shapes, only on the behaviours listed here (via `validate()` and, later, `evaluate()`/introspection). Where a mechanism note conflicts with a spec doc, the spec wins ([v3-implementation-notes.md](v3-implementation-notes.md) header rule)._

## A · What the artifact is — the four products of the parse pass

One walk over the raw input, once per distinct input, produces ("One spine, three views" in [v3-evaluator-methods.md](v3-evaluator-methods.md)):

1. **The canonical AST.** Shorthand faces, operator symbol aliases and namespace aliases (`$d` → `$data`, …) are normalized away; positional payloads are mapped onto named parameters via `positionalParams`; the compiled tree holds canonical names only — evaluation and tooling never see a spelling. ("Shorthand grammar" and "Naming rules" in [v3-api.md](v3-api.md); "The runtime interface" in [v3-operator-contract.md](v3-operator-contract.md).)
2. **The hole list.** Every maximal evaluable node, tagged with its **path in the input as authored** — the same paths `FigTreeError` is tagged with in report mode and editor diagnostics. A node root is the degenerate case: one hole at path `[]`. ("Subtleties to resolve at implementation" in [v3-implementation-notes.md](v3-implementation-notes.md); worked examples 1–2 in [v3-worked-examples.md](v3-worked-examples.md).)
3. **The issue stream.** Every _option-independent_ static error and warning, in deterministic tree order. Option-dependent checks (`maxDepth`/`maxNodes`, the sample-data warning) are **never stored** — they run per `validate()`/`evaluate()` call against obligations B4 and B6. ("The check inventory" in [v3-evaluator-methods.md](v3-evaluator-methods.md); option-independence below.)
4. **Constancy classification.** Bottom-up: a subtree is constant iff it contains no operator/fragment node and no reference string; everything inside `literal` is constant by fiat, unwalked; non-plain values (class instances, `Date`s, functions) are opaque constants, never traversed. Constancy powers the identity short-circuit, hole extraction, "literal parameter" detection for static checks, and shielding. ("Parse → compile → evaluate" step 2 in [v3-implementation-notes.md](v3-implementation-notes.md); "Non-plain-object values: opaque constants" in [v3-api.md](v3-api.md).)

## B · Precomputations riding the artifact

1. **Skeleton + holes.** A plain-literal root (or any plain literal containing evaluable descendants) compiles to a constant skeleton plus `(path, compiledNode)` holes; zero-hole literals evaluate as identity. ("Parse → compile → evaluate" step 3 in [v3-implementation-notes.md](v3-implementation-notes.md).)
2. **Shielding.** Per hole: a `staticFallback` constant, present iff the hole root's `fallback` subtree is classified constant — an `operatorDefaults` modifier fallback (`plus: { fallback: 0 }`) counts. Expression-level: one `shielded` flag, true iff every hole has one. Powers the `validate()` badge (3.3) and timeout assembly (Phase 10). **Amended at Phase-11 planning (Carl, September 2026): a fragment-call hole with no call-site `fallback` lifts the static fallback of its target's body root.** Without the lift, factoring logic into a fragment silently loses shielding — the hand-written `{ $http: …, fallback: null }` is shielded, the identical logic behind a fragment call is not, because the authored fallback now sits on the body root where this rule never looked. Same intent, different timeout behaviour, purely from where the expression was written: the principle a fragment behaves as its expansion does, broken by an accounting gap. The lift is sound because the call's value _is_ the body root's value, so the constant the author declared there is exactly what assembly would splice. The lift is computed at registration and stored on the compiled fragment; a call-site `fallback` still wins where authored. The planning ruling scoped it to a body root that is an operator or fragment-call node with a constant fallback, judging a skeleton-rooted body's per-hole treatment not worth it. **Widened at the Phase-11 PR review (Carl, September 2026): every shielded body lifts, skeleton roots included.** The premise did not survive the build — `splice()` already assembles a skeleton from per-hole values for two callers (deep evaluation and the shielded path), so the skeleton case is a third call to it rather than new machinery, and it was moved from `src/evaluate/evaluate.ts` to `src/parse/artifact.ts` so registration can reach it without the parse layer depending on the runtime. The narrow scope also left the principle half-closed: a preset config object with a constant fallback on each embedded expression is a bread-and-butter fragment shape, and factoring one out unshielded it exactly as the operator-root case did. The condition is therefore just `artifact.shielded` — every hole answers, or the body does not lift. **One place a call is not exactly its expansion, recorded rather than resolved:** a call is ONE hole at its call site, so it contributes all of its fallbacks or none, where the same expression inline degrades hole by hole and can mix real values with placeholders. That is the conservative direction — a body that half-finished cannot hand a half-real value through a boundary that has already returned a single one — and it is inherent to the call being one hole, not to the lift. _Built at Phase 11, corrected at its review: the registration-time computation reads the body artifact's own holes, so the lift needs no second implementation of what makes a fallback static — and `rootHoles` names a hole by its node's path rather than `[]`, which a body parsed under a base path requires. The review also caught the lift failing to compose through a nested call: a hole that is itself a call was read from the artifact, where the walk had recorded `undefined` because it compiled in pass 2 and no target is folded before pass 4. Such a hole resolves against the registry instead, which the fold's reverse topological order makes well-founded — so the lift is transitive, and `outer → wrapper → slowFrag` shields._ ("Timeout shielding rides the compile artifact" and the invalidation-set entry in [v3-implementation-notes.md](v3-implementation-notes.md); fallback rule 3 in [v3-api.md](v3-api.md).)
3. **Delivery-mode binding.** Each compiled parameter is bound to its declared evaluation mode from registry metadata at parse — "lazy branches become structure rather than behaviour". Constants under lazy declarations become pre-resolved handles (the degeneration rule) — the _binding_ is recorded now; the handle machinery is Phase 4. ("Step 2" in [v3-worked-examples.md](v3-worked-examples.md); "Evaluation modes" in [v3-operator-contract.md](v3-operator-contract.md).)
   - **Amended September 2026 (Phase 5): binding through the registry is not enough for the container modes — they need their own compiled shapes.** `lazyElements`, `race` and `lazyEntries` each hand the body one individually-demandable unit per element or entry, and B1's skeleton cannot express that: its holes are _maximal_, so a partly-constant element (`{ name: '$data.n' }` inside a `firstOf` list) dissolves into the enclosing shape and stops being a node at all — two holes for three elements, one of them two levels deep, and no node to build element 1's handle from. So a literal container at one of those modes compiles to `ElementsNode` (`nodes: CompiledNode[]`) or `EntriesNode` (`entries: Record<string, CompiledNode>`, plus a consumed `vars` block) instead of flattening. Rules: **parameter position only** — never a root, never a container child, never dispatched by the evaluator; **only when at least one child is non-constant**, so an all-constant literal stays a `ConstantNode` and reaches the body through the degeneration rule, which is what keeps it visible to `validate` hooks (they see constant parameters only) and the `{ $and: [] }` / `{ $firstOf: [] }` dead-expression warnings alive; and an element's index is its **position in `nodes`**, never its authored path's tail, which a leading positional shifts — the body's ordering obligations (`race`'s lowest-index failure rule) are parameter-relative. Both are structure, not work, so neither counts toward B4. A branch map keeps the ordinary plain-object key rules (`//` stripped, `vars` consumed, stray `$name` warned), and the literal-vs-dynamic decision is the standard node classification — which is what makes a branch key named `operator` the loud error the passes record.
4. **Counts.** `nodeCount` and `maxDepth` measured and stored as numbers; `literal` contents are never counted. Limits are compared per call, never baked in. **Amended September 2026 (Carl) — `nodeCount` counts _evaluable_ nodes, not every walked value** (_provisional: up for further refinement_). The wound: counting every visited value made a 200-entry options list 601 nodes, so inert data tripped a limit meant for runaway logic, and the number was uncalibratable ("no config should hold more than N values" is not a judgement anyone can make, where "no expression should invoke more than N operators" is). Walk cost on untrusted input is bounded instead by a **built-in, option-independent ceiling enforced mid-walk** — not by the user's option, which like `maxDepth` is a post-hoc comparison and so reports size rather than preventing work (see the recursion-ceiling defect in [v3-implementation-notes.md](v3-implementation-notes.md)). The ceiling is never stored; only the two measured numbers are. _Amended again at Phase 5: the evaluable set is stated **positively** in the code, so a newly-added node kind is structure until someone deliberately counts it — the element/entry shapes (B3) were the first test of that, and are not counted. `maxDepth` also gained a level on the rest-slice path, which had never recorded its synthetic container: an expression now measures the same depth through its shorthand face as through its canonical one._ _Built (Phase 4, September 2026): evaluable = operator, fragment-call, reference and invalid placeholder nodes — constants and plain containers are structure, not work; the ceiling is `DEPTH_CEILING = 500` (src/parse/probe.ts), one ceiling on depth only, reported as an error issue with code `depth-ceiling` at the node where descent stopped._ _Built at Phase 11: the walk records each resolved call site with its depth and `composeRollups` (src/parse/parse.ts) applies the two rules, shared by artifact assembly and by registration's reverse-topological fold — a body compiled before its callee would otherwise compose against zeros, since bodies compile in key order and dependency order is only known afterwards._ _Amended at Phase-11 planning (Carl, September 2026) — both numbers count **through** fragment calls, by composition rules that differ because the quantities do. `nodeCount` is a total, so a call site adds its target's transitive count, twice for two call sites: two calls are two evaluations of the body. `maxDepth` is a maximum along a path, not a total, so it composes as `max(current, depth + target.maxDepth)` at the call node — a global sum over-reports (a caller measuring 10 with a depth-3 call into a depth-4 body is 10 deep, not 14). A body's own `maxDepth` is measured from its own root at 0, which is what makes the offset exact. Rolled up at registration in reverse topological order, well-founded because the recursion ban makes the fragment graph a DAG; without it the guards stop meaning anything the moment logic moves into a fragment._ ("The full invalidation set" in [v3-implementation-notes.md](v3-implementation-notes.md); "`literal` boundaries" there.)
5. **Compiled literal regexes** — **slot reserved, mechanism deferred** (Carl, September 2026, at Phase 7.2). The drafted obligation: a literal `pattern` compiles once at parse, the same moment the validate hook checks it; dynamic patterns compile per evaluation; `lastIndex` state never leaks. What shipped: the last clause, by construction — `regex` constructs its `RegExp` **per use**, so no global-scan state can survive a call, and `mode: 'match'` builds its own global-flagged instance. The precompute did not ship, because nothing can write this slot: a definition has no way to contribute one, and the hook it would take (a definition-level `precompile` plus a channel on `OperatorContext`) buys little against a `RegExp` construction the engine already caches by source and flags. The slot keeps its reservation and the hook stays non-breaking to add, should a measurement ever ask for it. ("String primitives are shared functions too" in [v3-implementation-notes.md](v3-implementation-notes.md).) ("String primitives are shared functions too" in [v3-implementation-notes.md](v3-implementation-notes.md).)
6. **Dependency recording.** Statically-known `$data` paths (literal `get` paths included via the sugar equivalence — _built at Phase 7.1, with the `get` half added there: a literal `path` with no `from` joins the list, a computed one sets `dynamic`, and a supplied `from` contributes neither, the read not being against `$data` at all_; `[*]` projections as written), the `dynamic` flag (computed `get` path, bare `$data`, dynamic fragment arguments), canonical operators invoked, fragments called. Consumed by the sample-data check now (3.3) and `getDependencies()`/`isEvaluable()` later (Phase 13). ("`getDependencies()`" in [v3-evaluator-methods.md](v3-evaluator-methods.md).)
7. **Result-key skeletons** (deliberately deferred, recorded so it isn't lost): the artifact _may_ precompute cacheable nodes' result-key skeletons — a micro-optimization for Phase 9, not a coupling. ("Two caches, deliberately disjoint" in [v3-implementation-notes.md](v3-implementation-notes.md).) **Assessed September 2026 (Carl) — almost certainly not to be built**, on two objections, both his. (a) _It rides one artifact._ The skeleton sits on a node inside one expression's artifact, so a second expression spelling the identical request gets no shortcut — it builds its own key at its own parse. The _result_ entry is still shared, since both spellings produce the same key string; only the assembly shortcut is per-artifact, which is precisely what "key assembly, not key sharing" was ruling out. (b) _Parse-time work is unconditional; evaluation is not._ Eager precompute pays for every branch never taken, every `fallback` that never fires and every iterator body over an empty array — and pays it on the **cold first call**, the one case the benchmark plan (Phase 16) already flags as where v3 could plausibly lose to v2 outright. For an expression parsed and evaluated once it is pure loss. Lazy memoize-on-first-use answers (b), but writes memo state into a structure the design treats as read-only and shared across evaluations, downgrading "the artifact is immutable" to "immutable except for memo slots". A **side table** keyed on node identity (a `WeakMap<CompiledNode, string>` held beside the parse cache — Carl's "KeyStore", September 2026) keeps the artifact literally immutable, dies with its artifact so it needs no invalidation, and is the mechanism to reach for should any per-node derived state ever warrant memoizing. None of the three is justified by the saving actually in question: one serialization per _parse_ instead of one per _evaluation_ — sub-millisecond across hundreds of evaluations, sitting behind a network call three orders of magnitude larger. The slot keeps its other tenant, compiled literal regex patterns, where the per-evaluation saving is a real `RegExp` construction and the value provably cannot change (objection (b) still applies there in miniature — a pattern in a never-taken branch compiles for nothing — but the payoff ratio is far better and the eager cost is bounded by the count of literal patterns in the document).

## C · Independence and self-containment rules

1. **Option-independent.** No option-dependent result is baked in, so per-call options never affect the artifact — and per-call `operators`/`fragments` do not exist at all (registry stability, Options area). The only thing that ever invalidates an artifact is an `updateOptions()` touching one of the three registry-affecting keys — `operators`, `fragments`, `operatorDefaults` — which exist at construction/`updateOptions()` only. ("The full invalidation set" in [v3-implementation-notes.md](v3-implementation-notes.md).)
2. **Data-independent.** One compile serves every `data` input forever. ("Step 5" in [v3-worked-examples.md](v3-worked-examples.md).)
3. **Registry resolution baked in.** The artifact records which `$name` keys invoke and which are inert, and holds resolved registry entries (`instanceDefaults` included) — which is _why_ the artifact is per-instance and why per-call `operators`/`fragments` don't exist. _Built for fragments at Phase 11: a resolved call node carries its `FragmentEntry` exactly as an operator node carries its `RegistryEntry`, so the compiled body a call splices is a pointer rather than a lookup — and fragments live in the same registry object as operators and aliases, one collision domain, one thing to invalidate._ ("Parse → compile → evaluate" step 4 in [v3-implementation-notes.md](v3-implementation-notes.md).)
4. **The input is never mutated**, and compiled constants/skeletons may share structure with it — the results-are-immutable and don't-mutate-evaluated-expressions contract lines. ("Result immutability — the ruling" in [v3-evaluator-methods.md](v3-evaluator-methods.md).)
5. **Identity-only marking.** An input containing opaque constants is flagged identity-only: it must never be served from the content-keyed cache layer (two such expressions can serialize identically and splice the wrong constants). Consumed by Phase 8.2. _Built (September 2026), with a correction: there are **two independent guards**, and this flag is the weaker of them. It is set only for opaque values the parser **walks**, and a `literal` payload is never walked — so an opaque value inside one leaves the flag `false`. The content-key serializer walks the raw input instead and refuses any non-plain value, which catches that case and every other. Both ship, and neither should later be dropped as redundant: the serializer is load-bearing, the flag is belt and braces._ ("Cache keying for non-identical inputs" in [v3-implementation-notes.md](v3-implementation-notes.md).)
6. **Comments and `vars` are consumed.** `//` keys are stripped everywhere (except inside `literal`); plain-literal `vars` blocks scope their subtree and are removed from the compiled skeleton. ("Comments: the `//` key" and "`vars` on plain object literals" in [v3-api.md](v3-api.md).)
7. **`undefined` is normalized at parse** per JSON semantics: `{ a: undefined }` = absent key, `[1, undefined]` = `[1, null]` — the parse half of boundary normalization. ("The value domain" in [v3-api.md](v3-api.md); "Null policies and boundary normalization live in the engine" in [v3-implementation-notes.md](v3-implementation-notes.md).)
