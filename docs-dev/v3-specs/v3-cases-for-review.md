# FigTree v3 — the absence / failure / default gradient — settled rulings

*Register of the gradient rulings collected during the operator parameter passes: for each edge case, does it yield `null`, fire `fallback`, or error? The end-of-passes **group review has taken place** (Carl, July 2026, concluding from the null-policy review — [v3-null-policy-review.md](v3-null-policy-review.md)): every row below is **agreed**, and this register is now the consolidated behaviour reference. Its rows override any stale *Provisional — #N* markers left in the passes (kept there as pointers); row numbers are stable, since the passes cite them. Per-row rationale and the considered alternatives live in the passes and in this file's git history. Revisit deliberately, not casually.*

## The two former headline questions — resolved (Carl, July 2026)

- **`fallback` means failure, only** — fixed point 1 confirmed as drafted throughout. The **`…Default` parameter family** is the softer catch for absence: `if.else`, `match.default`, `find.noMatchDefault`, `regex.noMatchDefault`, `get.missingPathDefault`, `sql.noRowDefault`, and the null-replacement `nullValueDefault` / `nullInputDefault` (ledger #18). Parameters answer *absence*, `fallback` catches *failure*, and the two compose on one node. The acknowledged cost — authors face a "fallback or `…Default`?" choice — is accepted, mitigated by editor and `validate()` guidance rather than by collapsing the distinction.
- **Null operands `propagate`** (row 3 and its cells) — confirmed as the unadorned default, with `nullValueDefault` as the declared per-site / host-wide opt-out. **Recorded reservation (Carl)**: a future flip to reject (null operand = error) remains on the table — see Open items, below.

## Fixed points — confirmed

1. **Absence is not failure**: a missing `$data` path yields `null` (never throws, absent `strictDataPaths`); `fallback` triggers on node *failure* only. (References § Absence semantics; Node grammar § `fallback` semantics)
2. **Null policies are per-parameter metadata** — `propagate` / `value`, declared exactly where the parameter's type names `null`; admission is type-driven (null at a required/element position is legal only where `null` is a named type member), so `reject` is derived from the type, never declared. `propagate` is the default for value inputs. (Type § Null policy)
3. **Null at an optional parameter means unset** — the type-driven rule governs required/element positions only; optionals keep null-means-unset with clean types, unless the type names `null` deliberately. (Type § Optional parameters)
4. **Empty aggregate input is an error**, excepted only where the identity element is unique and type-stable. (Type § Aggregates; the generating rule from the `and`/`or` pass, batch 1)

## The case matrix

Rows 2 vs 3 remain the sharpest deliberate contrast in the set: an *empty* sum is a failure a fallback can catch, while a sum with a *null operand* succeeds as `null` and the same fallback does nothing. The tools differ accordingly — `expect` or a default `fallback` for emptiness, `nullValueDefault` for null operands — and both rulings follow from the confirmed fixed points.

## Open items

1. **Row 3's reservation (with row 13 attached)**: Carl may yet flip null operands from `propagate` to reject (a null operand = error, caught by `fallback`). Parked deliberately as a single future decision — it re-touches every arithmetic operator at once (including the propagation-precedes-`expect` ordering in the `plus` pass), and `nullValueDefault` would become the way to *avoid* the error rather than the null.
2. ~~**The `length` seam**~~ — **closed (Carl, September 2026, at Phase-6 planning)**: the difference stands, and stands as *deliberate*. An iterator **does** something with a collection, so a missing one is a genuine failure worth naming at the iterator; `length` **measures** one, and a measurement of nothing composing quietly to `null` is the standard gradient doing its job — `{ $greaterThan: [{ $length: '$data.tags' }, 0] }` degrading to falsy is the useful reading, not a trap. It is also the reversible direction: `propagate` can be tightened later, a reject relaxed only by breaking callers. `length` is unchanged.
