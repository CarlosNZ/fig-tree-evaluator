What this page leaves out

  • Null policies. Every parameter has one, and they are decided per parameter — propagate, value, or reject-by-type. The consolidated view is the null-policy review sheet; a second copy here would fall out of sync on its first edit.
  • Node-level reserved keys, which are not parameters: fallback, vars, useCache, and the // comment key.
  • Candidate parameters not yet adopted: emptyDefault on min/max, and missingPathDefault on http/graphQL.
  • Parameter-name aliases — they do not exist in v3, so each name shown is the only spelling.

A count discrepancy, since resolved

The canonical list used to head itself “42 core + 3 I/O operators” over a table of 41 core rows, and the M3 milestone in the implementation plan said “all 42 core operators” — both consistent with substring having been cut from core during the string batch without the headline counts following. Corrected in the specs at Phase 7, to 41 core: 40 defineOperator() definitions plus literal, which is grammar and has none. The 13 symbolic aliases were correct as stated.
